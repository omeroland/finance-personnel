## Objectif

Écrire la couche d'accès aux données avec sqlc et pgx v5.

- Requêtes dans `store/queries/*.sql` ; chaque requête filtre par `owner_id`.
- Interfaces de dépôt consommées par `http/` : liste de suivi, faits annuels, instantané, qualitatif, évaluations, jobs d'import.
- Écriture des faits avec priorité des sources : une valeur `manual` n'est jamais écrasée par `xlsx` ou `provider` ; une valeur entrante différente crée une ligne `fact_conflict`.
- Chaque écriture dans une transaction, avec une ligne `core.audit_log`.
- Archivage d'une évaluation : insertion seule, empreinte des entrées = SHA-256 du JSON canonique.

## Hors portée

## Critères d'acceptation

- [ ] Une valeur manuelle survit à une écriture `xlsx` différente, et un conflit est créé
- [ ] Une écriture identique ne crée ni conflit ni ligne d'audit
- [ ] Le propriétaire B ne lit aucune donnée du propriétaire A (test sur chaque requête de lecture)
- [ ] Chaque écriture produit exactement une ligne d'audit
- [ ] `make test-int` réussit

## Contraintes

Pas d'ORM. Pas de SQL construit par concaténation de chaînes.
