## Objectif

- Workflow déclenché par une étiquette `v*` : construction des images, signature cosign (sans clé, OIDC GitHub), envoi vers GHCR.
- Déploiement par SSH : `compose pull` puis `up`, secrets déchiffrés par sops sur le serveur (clé age du serveur).
- Import du realm de production (sans client de test).
- Test de fumée après déploiement : `/healthz`, page de connexion, certificat TLS valide.
- Retour arrière documenté : redéployer l'étiquette précédente.

## Hors portée

Infrastructure du VPS elle-même (préparée par toi).

## Livrables

- `.github/workflows/deploy.yml`
- `deploy/README.md` (déploiement et retour arrière)

## Critères d'acceptation

- [ ] Une étiquette déploie la version ; le test de fumée passe
- [ ] Le serveur refuse une image non signée
- [ ] Retour arrière vers l'étiquette précédente testé une fois

## Contraintes

Aucun secret en clair dans les journaux du workflow.
