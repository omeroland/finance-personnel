## Objectif

Protéger l'API et décrire le realm Keycloak sous forme de fichier.

- Middleware `platform/auth` (go-oidc v3) : signature par JWKS en cache, `iss` du realm, `aud` = `finance-api`, `exp`, algorithme RS256 seulement ; `owner_id` = `sub` (D1) posé dans le contexte.
- `/healthz` et `/readyz` sans jeton ; tout le reste exige un jeton.
- `deploy/keycloak/realm-finance.json` : realm `finance`, client public `finance-web` (code + PKCE S256, URI de redirection paramétrées), mapper d'audience `finance-api`, durée des jetons d'accès 5 minutes.
- `deploy/keycloak/realm-finance-test.json` : copie pour les tests seulement, avec un utilisateur et un client de test autorisant l'obtention directe de jetons. Jamais importée en production.

## Critères d'acceptation

- [ ] Sans jeton : 401 `problem+json`
- [ ] Jeton d'un autre realm : 401
- [ ] Jeton expiré : 401
- [ ] Jeton signé HS256 avec la clé publique comme secret : 401
- [ ] Jeton valide : 200 et `owner_id` = `sub`
- [ ] Le realm de production n'autorise pas l'obtention directe de jetons (test sur le fichier)
